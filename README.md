# Chest Memory — Sunshine's Dels

Клановый мод для **Sunshine's Dels**, автор **Karandash**. Fabric 26.1.2 / 26.2.

Клиентский мод: память сундуков **по каждому миру и серверу**, панель **Ё**, подсветка, **Jade**, сбор для **Litematica**.

## Возможности

### Память
- Сундуки, бочки, шалкеры, воронки, раздатчики, эндер-сундук, шалкеры в инвентаре
- **Двойной сундук = 1 контейнер** (обе половины → один ключ)
- **Отдельный файл на каждый одиночный мир и каждый сервер** (`host:port`)
- Данные разных серверов **не смешиваются**

### Панель Ё
- **Вкладка мира/сервера** — переключайся и смотри, что есть в других профилях
- ★ = текущий мир (LIVE); остальные — только просмотр
- Поиск, фильтр, количество справа
- Экспорт CSV

### Подсветка
- 20 секунд, полный блок (двойной — оба блока)
- Подсветка слотов в GUI
- Waypoints

### Jade (опционально)
- При наведении на контейнер сверху: **всего предметов**, число видов, иконки с количеством
- Если ещё не открывали: «ещё не сканировали»

### Сбор
- **Соло** — клик по материалу схемы строит маршрут по сундукам, где он лежит
- **Клановый** — сбор на несколько человек через хаб, вход по коду `CM-XXXX`
- Бронь предметов: видно, кто что взял; порядок кликов — порядок сбора
- Склад: помеченные сундуки, сдача считается автоматически при закрытии сундука
- Пустые ячейки как в ванильном контейнере, при наведении — остаток в стаках и в ШБ
- Лента событий: кто взял, кто сдал, кто отключился. Историю ведёт хаб, поэтому она
  переживает перезаход и видна тем, кого не было в игре

### Инструменты создателя сбора
- Переименовать сбор, удалить участника
- **ПКМ по ячейке** — убрать предмет из сбора (чернеет, не бронируется, не считается в прогресс)
- **Shift+ПКМ по ячейке** — снять бронь с одного предмета
- Сбросить сразу все брони — в настройках сбора
- Выйти из сбора, не закрывая его для остальных
- Работает и на офлайн-лаунчере: при создании сбора выдаётся секрет создателя,
  который заменяет проверку Mojang для этих действий

## Установка

1. Minecraft **26.1.2** или **26.2** + Fabric Loader + Fabric API  
2. (по желанию) **Jade**, **Litematica** под ту же версию игры  
3. `build/libs/chestmemory-2.4.4.jar` → `mods` (старый jar удалить)  

Один jar подходит для **26.1.2** и **26.2**.

## Клановый хаб

Хаб — свой сервер, `hub/clan_hub.py` (systemd, см. `hub/deploy_vps.sh`). Настройки в
`/opt/chestmemory-hub/env`:

| Параметр | Смысл |
|---|---|
| `REQUIRE_AUTH` | `1` — каждое изменение требует подтверждённой личности Mojang. `0` — нужно для пиратских лаунчеров: они не проходят рукопожатие и иначе не смогут даже войти в сбор. При `0` участников можно подменять, поэтому задайте `CLAN_TOKEN`. |
| `CLAN_TOKEN` | Общий секрет. Задан — хаб не отвечает тем, у кого нет вашей сборки мода. Вшивается в jar: `./gradlew build -Pclan_hub_token=…` |
| `SESSION_TTL_SEC` | Сколько живёт сбор без активности. По умолчанию 30 дней. Опрос от любого участника продлевает срок, так что сбор держится, пока кто-то заходит в игру. |
| `UNSTARTED_SESSION_TTL_SEC` | Короткий срок для сбора, куда ещё ничего не сдали (по умолчанию 7 дней) — против брошенных и спама. Первая же сдача переводит сбор на полный срок. Старое имя `SOLO_SESSION_TTL_SEC` тоже понимается. |
| `MAX_SESSIONS_PER_HOST` | Сколько сборов может быть открыто у одного создателя, по умолчанию 50. При превышении хаб отвечает 409 с причиной `host_session_limit` и списком занятых кодов — это квота, а не ограничение темпа, поэтому ожидание не поможет: закройте лишний сбор. |
| `MAX_SESSIONS_TOTAL` | Предел на весь хаб, по умолчанию 512. Каждое изменение перезаписывает всё хранилище целиком: сбор на 40 материалов — около 5 КБ, так что 512 обычных сборов это ~2,7 МБ. |

Действия создателя (переименовать, удалить участника, снять брони, убрать предмет,
закрыть сбор) требуют либо подтверждённой личности, либо секрета создателя. Один uuid
не подходит намеренно: он виден всем в ростере, и раньше его хватало, чтобы закрыть
чужой сбор.

Проверить хаб после обновления: `python3 hub/hub_e2e_check.py` — гоняет отдельный
экземпляр на своём порту и не трогает рабочие данные.
